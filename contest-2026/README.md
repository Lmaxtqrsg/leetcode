## 五、语法卡点本

| 语法点 | 出现次数 | 错误写法 | 正确写法 | 状态 |
|---|---|---|---|---|
| 整数除法截断 | 2 | `sum / n` | `(double)sum / n` | 已过关 |
| 保留两位小数 | 1 | `cout << norm` | `fixed << setprecision(2)` | 已讲透 |
| int 溢出 | 2 | `int sum` | `long long sum` | 已过关 |
| 自定义类型作参数 | 1 | `bool cmp(struct )` | `bool cmp(stu a, stu b)` | 已讲透 |
| 大数组开局部 | 1 | main 里 `stu S[100005]` | 开在 main 外面 | 已讲透 |
| 数组开多大 | 1 | `stu S[20]` | 按数据范围 `n_max + 5` | 已讲透 |
| 读入顺序 | 1 | 按记忆写 | 严格按题面字段顺序 | 已讲透 |
| cmp 只写 `>` 分支 | 1 | `if (a.sum > b.sum) return true;` | `if (a.sum != b.sum) return a.sum > b.sum;` | 新 11-04 |
| cmp 末尾漏 return | 1 | 三个 if 之后直接结束 | 最后一行无条件 `return 比较表达式;` | 新 11-04 |
| cmp 比错字段 | 1 | `a.num > b.sum` | 两边必须同一种量 | 新 11-04 |
| 四舍五入 | 1 | `double` + `printf("%.1f")` | 整数缩放：`(w + 5) / 10` | 新 11-04 |
| 格式设置位置 | 1 | `cout << x << fixed << setprecision(1)` | 先设格式，再输出值 | 新 11-04 |
| setprecision 对 int 无效 | 1 | `setprecision(1) << int` | 转 `(double)` 或手工拼 `k/10`、`k%10` | 新 11-04 |
| `%` 用于 double | 1 | `double x; x % 10` | 只有整型能取模，改 `int` | 新 11-04 |
| cin 之前调用依赖输入的函数 | 1 | `prec(op1,op2,...)` 写在 `cin >>` 之前 | 所有依赖输入的调用必须排在 cin 之后 | 新 11-05 |
| 多组数据漏读 N | 1 | 直接 `cin >> A` | 先 `int N; cin >> N;` 再 `while (N--)` | 新 11-05 |
| 只打印不计算 | 1 | `cout << A << op1 << B` | 先把结果算进变量，再输出结果 | 新 11-05 |
| 空容器取 top | 1 | `while(a){...} S.top()` | 空 stack/queue/vector 不能 top/front/pop | 新 11-05 |
| 进制转换不补前导零 | 1 | `4` 只得到 `100` 三位 | 固定宽度从右往左填，或干脆用位运算 | 新 11-05 |
| 该用位运算却去转二进制 | 1 | 十→二→取位（绕一圈） | `(x >> k) & 1`；多位判断用 `x & 掩码` | 新 11-05 |

## 七、环境备忘（踩过的坑）

1. **大数组一律开全局。** 局部变量在栈上，Windows 默认 1MB；`stu S[100005]` 约 4MB，一进 main 就崩，现象是"程序没法输入"。
2. `endl` 每次 flush，循环里用 `"\n"`。
3. 用 `printf` 要 `#include <cstdio>`。
4. 提交前固定三行：`输入：… 实际：… 期望：…`。
